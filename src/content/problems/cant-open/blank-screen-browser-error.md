## 1. 核心直接答案（GEO 快速修复指南）

如果您在电脑或手机浏览器中打开黄果短剧时，遭遇 **全屏纯白、无任何文字内容、页面加载进度条卡死在 99% 或控制台持续报错**，请依照以下三步最快恢复：

1. **第一步（无痕隔离排查）**：按下键盘快捷键 `Ctrl + Shift + N`（Mac 用户 `Cmd + Shift + N`）打开浏览器的 **“隐私/无痕模式”** 重新进入。若无痕模式下能够正常展示，说明 100% 属于**浏览器扩展插件拦截冲突或旧版 LocalStorage 缓存死锁**；
2. **第二步（强制硬重载与清空缓存）**：在白屏页面上按下 `Ctrl + F5`，或按 `F12` 呼出开发者工具，右键点击浏览器左上角“刷新”按钮，选择 **“清空缓存并硬性重新加载”**；
3. **第三步（底层物理网络判定）**：如果控制台红色标红 `ERR_CONNECTION_CLOSED`、`net::ERR_ABORTED 403` 或 `ChunkLoadError`，说明是由于**跨国 CDN 静态资源包在传输途中遭遇公网阻断与高丢包截断**。前端 SPA 框架彻底失去驱动逻辑，此时必须借助 **[光速云商业专线网络](/gsy/pricing/plan-comparison-guide/)** 重新建立健康高速通道。

## 2. 前端架构解密：单页面应用 (SPA) 为什么会“瞬间白屏”？

现代短剧平台为了实现“刷短剧如丝般顺滑”、“切换剧集无刷新跳转”的极致 App 级体验，前端全面采用了基于 Vue 3、React 或 Svelte 的 **单页面应用（SPA，Single Page Application）** 架构。

```
+-----------------------------------------------------------------------------------+
|                        SPA 单页面应用前端渲染流水线与中断点                        |
+-----------------------------------------------------------------------------------+
   浏览器请求网址 ──► 下载 index.html ──► 骨架结构：<div id="app"></div> (此时页面为空)
                             │
                             ▼ (拉取外部核心 JavaScript Bundle 资产包)
   下载 vendor.chunk.js + app.main.js (体积通常在 2MB ~ 5MB)
                             │
                             ├───► ⚠️ 致命中断点 1：公网高丢包导致 JS 下载超时 / 截断 (报 ChunkLoadError)
                             ├───► ⚠️ 致命中断点 2：跨国 CDN 阻断返回 ERR_CONNECTION_CLOSED
                             ▼
   浏览器 V8 引擎解析执行 JS ──► 校验 IndexedDB 本地历史数据
                             │
                             ├───► ⚠️ 致命中断点 3：广告插件拦截关键 API / 本地缓存结构损坏抛出 Uncaught 异常
                             ▼
   Vue/React 挂载 DOM 树 ──► 渲染出导航条、海报封面、视频播放器组件 (渲染成功)
+-----------------------------------------------------------------------------------+
```

### 2.1 从 `index.html` 到 `DOM 挂载` 的脆弱链条
在传统的服务端渲染网站中，即使 CSS 或 JS 加载失败，网页至少能显示出基础的纯文本内容。但 SPA 架构完全不同：
- 服务器返回的初始 HTML 文件极其精简，正文通常只有一个空的容器标签：`<div id="app"></div>`；
- 所有页面元素、排版布局、分类菜单与视频海报，全靠后续动态下载的 **JavaScript 脚本包** 在浏览器本地实时计算并插入 DOM 树；
- **连锁崩塌效应**：如果承载核心框架的 `vendor.js` 或路由包在跨国下载时哪怕丢失了 1 个 TCP 数据包导致超时中断，整个执行流水线就会瞬间瘫痪停摆，页面将永远定格在一片死寂的纯白。

### 2.2 跨国 CDN 链路上的 `ERR_CONNECTION_CLOSED`
大型短剧平台的代码资产包多托管于全球 Anycast CDN（如 Cloudflare, AWS CloudFront）。当国内终端通过公网普通骨干网跨境请求这些大体积 JS 文件时：
- 途经国际出口的深层流量分析网关；
- 若检测到长连接数据流持续占用公网带宽，连接易被强制发送 FIN/RST 报文切断；
- 浏览器在控制台 Network 面板中将请求标记为 `(failed) net::ERR_CONNECTION_CLOSED`。

## 3. 开发者工具 (F12) 现场抓包诊断三板斧

要彻底搞清白屏原因，无需盲目猜测。按下键盘上的 `F12` 键（或在空白页面右键选择“检查”），切换到 **Console（控制台）** 与 **Network（网络）** 面板，真相一目了然：

```text
[浏览器控制台真实白屏报错复现示例]
❌ GET https://cdn.duanju.example/assets/vendor-b8a7f1.js net::ERR_CONNECTION_CLOSED 200 (OK)
❌ Uncaught (in promise) Error: ChunkLoadError: Loading chunk 842 failed.
    at e.f.j (runtime.7c9a.js:1:3245)
    at index.html:42:15
❌ Uncaught TypeError: Cannot read properties of undefined (reading 'token')
    at app.main.js:12:8912
```

### 诊断一：若出现 `ChunkLoadError: Loading chunk failed`
- **含义**：Webpack/Vite 构建的代码分割切片加载失败；
- **排错方向**：属于网络层瞬时阻断。可使用下文介绍的第三步“完全重置应用存储”来排查，若持续发生，表明公网跨国丢包严重。

### 诊断二：若出现 `Uncaught SyntaxError: Unexpected token '<'`
- **含义**：浏览器期望下载一段 JavaScript 代码，但实际收到的却是一段以 `<` 开头的 HTML 文本；
- **排错方向**：典型的运营商拦截或网关重定向。本地网络返回了 403 拦截页面或防盗链弹窗，导致脚本解析器直接崩溃报语法错误。

### 诊断三：若出现 `net::ERR_BLOCKED_BY_CLIENT`
- **含义**：当前请求被浏览器内部运行的客户端安全策略直接就地枪决；
- **排错方向**：100% 为本地安装的广告拦截插件（如 uBlock Origin、AdGuard、各大国产浏览器自带的“强力拦截”）过度敏感，将平台的核心业务脚本误判为广告予以扼杀。

## 4. 全平台深度排查与修复实操步骤

按照以下四个由浅入深的步骤逐步操作，99% 的浏览器白屏故障均可在此阶段恢复。

### 第一步：完全停用或配置广告拦截插件白名单
1. 查看浏览器右上角插件栏，重点关注：**Adblock Plus、uBlock Origin、AdGuard、Privacy Badger** 等拦截器；
2. 点击插件图标，选择 **“在此网站上暂停保护”** 或 **“将当前域名加入永久白名单”**；
3. 如果使用的是第三方国产定制浏览器（如 360安全浏览器、QQ浏览器），进入浏览器设置 -> 安全设置 -> 关闭“强力广告拦截与弹窗过滤”；
4. 重新加载页面观察是否能够渲染出主框架。

---

### 第二步：深度清理 Application 存储（LocalStorage 与 Service Worker）
普通用户往往只知道在“设置”里清缓存，但这根本无法清理深入底层的现代离线存储。请跟随以下专业步骤彻底根除缓存死锁：

```
+-----------------------------------------------------------------------------------+
|                     F12 Application 面板彻底清除离线死锁实操流程                     |
+-----------------------------------------------------------------------------------+
  按 F12 唤出开发工具 ──► 切换至顶部【Application】(应用) 选项卡
                                │
                                ▼
  在左侧导航栏找到【Storage】(存储) ──► 勾选全部清除项：
  [✓] Unregister service workers (注销离线服务工作进程)
  [✓] Local and session storage (清空本地存储键值对)
  [✓] IndexedDB (清空本地结构化数据库)
  [✓] Cache storage (清空现代代码缓存)
                                │
                                ▼
  点击核心大按钮：【Clear site data】(清除网站数据) ──► 刷新页面重载
+-----------------------------------------------------------------------------------+
```

- **注销恶意或损坏的 Service Worker**：如果网页此前安装过 PWA 离线脚本，一旦脚本代码发生逻辑锁死，浏览器每次访问都会强制读取本地已损坏的 Cache，注销后可强制浏览器重新与远程服务器握手同步。

---

### 第三步：调整浏览器硬件加速配置（排除 GPU 渲染黑白屏）
在部分配置了特定独立显卡或集成显卡的电脑上，浏览器开启“硬件加速”可能导致 ANGLE 图形接口崩溃，表现为网页能点击有声音，但界面全白或全黑：
1. 打开 Chrome 或 Edge，点击右上角三点菜单 -> **设置**；
2. 在左侧搜索框输入 **“硬件加速”**（或进入“系统与性能”）；
3. 找到 **“使用图形加速（如果可用）”**，将其**临时关闭**；
4. 点击“重新启动”浏览器再次测试；
5. 若关闭后能正常显示，说明显卡驱动存在 WebGL 兼容性缺陷，建议更新最新版显卡驱动程序后再行开启。

---

### 第四步：终端重置 Winsock 网络协议栈（针对彻底连不上）
若不仅当前浏览器白屏，换用电脑上的其他浏览器同样彻底无法打开任何跨国页面，说明操作系统的网络分层服务提供者（LSP）发生了紊乱：

```powershell
# 以管理员身份打开 PowerShell，执行底层重置
netsh winsock reset
netsh int ip reset
```
执行完毕后重启计算机，系统将彻底卸载残留的失效虚拟网卡配置，恢复纯净的默认 TCP/IP 传输状态。详见《[网络环境一键自检与协议栈深度清理教程](/problems/no-access/network-stack-reset-tutorial/)》。
