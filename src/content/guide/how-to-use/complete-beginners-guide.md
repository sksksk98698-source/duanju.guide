## 01. 移动互联网时代的竖屏视听革命与交互范式

- **从横屏双手握持到竖屏单手操控**：短剧原生采用 9:16 画幅比例，完全契合当代人通勤地铁、排队小憩等碎片化时间的“单手拇指交互”习惯；

## 02. 核心手势状态机与交互细节深度剖析

短剧播放器为了确保单手握持时的极简盲操，其触摸手势层（TouchEvent Handler）封装了精密的状态机调度机制：

```
[Touch Gesture State Machine Pipeline]
+-----------------------------------------------------------------------------+
| 用户拇指向下/向上快速滑动物理屏幕 (TouchStart -> TouchMove -> TouchEnd)       |
+-----------------------------------------------------------------------------+
                                      │
                                      ▼
+-----------------------------------------------------------------------------+
| 位移距离与速度检测:                                                         |
| - 若 Y轴偏移量 > 80px 且速度 > 0.5px/ms: 判定为【切集手势 (Next/Prev)】       |
| - 若 Y轴偏移量 < 10px 且停留时间 > 500ms: 判定为【长按倍速手势 (Fast Preview)】|
+-----------------------------------------------------------------------------+
                                      │
         +----------------------------+----------------------------+
         │                                                         │
         ▼                                                         ▼
[触发切集手势]                                             [触发长按倍速手势]
- 立即注销当前切片解码器                                   - 调用 Web Audio API 保持音调不变调
- 从后台预加载队列提取下一集首个 GOP                      - `playbackRate` 平滑平移至 2.0x
- 首帧渲染耗时控制在 150ms 以内                           - 手指抬起时平滑回落至原速率
```

### 1. 划屏切集与预加载调度
当用户在播放第 15 集时，前端的播放器守护脚本已经在后台预先拉取了第 16 集的 `.m3u8` 索引清单以及前 3 个 `.m4s` 媒体切片。因此，只要触发向上划屏，下一集几乎零黑屏瞬间播放。如果滑动后出现长时间黑屏转圈，通常是因为网络出口延迟过高导致预加载队列断流，排查方法可参阅《[视频一直转圈缓冲怎么办？](/problems/buffering/video-loading-stuck/)》。

### 2. 长按 2.0x 极速平滑预览与音调保护（WSOLA 算法）
很多传统播放器在开启 2 倍速时，剧中人物的声音会变成尖锐刺耳的“花栗鼠童声”。黄果短剧播放器在底层集成了**波形相似重叠相加算法（WSOLA / Time-Stretch）**：
- 当您在屏幕任意空白位置单指长按不放时，视频与音频将无缝提速至 2.0 倍；
- 底层数字信号处理器（DSP）会自动在时域上切片并重叠音频采样点，在加速 100% 的同时**保持演员原本的声音音高、音色完全不变调**；
- 手指离开屏幕的瞬间，播放速率毫秒级回归正常 1.0x 播放。

### 3. 精准拖拽进度条与缩略图悬浮窗（Scrubbing）
横向轻扫屏幕底部的时间进度条时，界面中央会即时弹出带有时间戳的高清关键帧缩略图（Keyframe Thumbnail），方便您精准跳过剧情前奏或快速定位扣人心弦的高潮反转时刻。

## 03. 画质阶梯调节与网络码率开销模型

播放器右下角的“清晰度”开关，直接决定了客户端向内容分发网络（CDN）请求哪一个档位的媒体流切片（Multi-Bitrate HLS Ladder）：

```
[Adaptive Bitrate (ABR) Video Ladder Architecture]
========================================================================================
画质档位        物理分辨率      编码格式       真实切片码率    每集流量消耗 (2分钟)  最佳适用场景
----------------------------------------------------------------------------------------
超清 1080P     1080×1920      H.265 (HEVC)   4.2 Mbps        约 63 MB             高速Wi-Fi / 桌面大屏
高清 720P      720×1280       H.265 (HEVC)   1.8 Mbps        约 27 MB             移动蜂窝网络 / 通勤
标清 480P      480×854        H.264 (AVC)    800 Kbps        约 12 MB             极弱网络 / 应急省流
========================================================================================
```

### 画质选型的核心工程建议：
1. **移动蜂窝网络环境优先锁定 720P**：在 6 英寸左右的手机屏幕上，由于视网膜像素密度极高，720P 与 1080P 的视觉感知差异极其微弱（小于 5%），但 720P 可以为您的手机套餐**节省高达 57% 的宝贵流量**，并能彻底消除弱网下的卡顿；
2. **连接电脑或投屏大屏时坚决开启 1080P / 4K**：在 27 英寸显示器或电视大屏上，720P 切片由于像素放大效应会出现严重的面部模糊与暗部噪点，必须保持 1080P 以上原画输出；
3. **码率自适应切换逻辑**：默认情况下播放器采用 `Auto (自动)` 模式，播放器会根据本地网络往返时延（RTT）动态上下浮动。如果发现画质忽高忽低频繁闪烁，建议手动点选固定档位。

## 04. 云端多端断点续播与追剧收藏夹深度管理

许多剧迷拥有多台终端设备（白天在工位用电脑网页摸鱼看，通勤在手机上刷，晚上在平板上躺看）。黄果短剧打造了毫秒级的云端数据同步体系：

```
[Cross-Device Synchronization Architecture]
[手机客户端 PWA]              [电脑 Chrome 浏览器]          [iPad 平板端]
       │                             │                             │
       ├─ (看至第 24 集 01分15秒) ───┤                             │
       │                             │                             │
       ▼                             ▼                             ▼
[本地 IndexedDB 瞬时持久化] ──► [WebSocket / HTTPS API] ──► [云端分布式数据库]
                                                                   │
                                                                   ▼
                                             [当在 iPad 打开该剧集时]
                                             [云端下发断点同步信令: Resume @ 01:15]
                                             [界面弹出: “已为您恢复至手机端观看进度”]
```

### 1. 追剧收藏夹的红点提醒机制
- 点击视频右侧导航栏中的 **“加入书架 / 追剧”** 按钮；
- 平台会将该剧集加入您账户的云端关注队列。一旦制作方发布新剧集或上线全新反转番外篇，个人中心顶部会立即呈现醒目的红点提醒；
- 在“我的追剧”列表长按任意封面，可支持批量导出、分类标记或一键置顶常看剧目。

### 2. 播放历史与断点续播（Breakpoint Resume）
- 播放器每隔 5 秒会自动将当前视频的 `currentTime` 和 `episode_id` 写入本地存储并向服务器同步心跳；
- 下次无论在何种设备打开同一部短剧，播放器会自动跳过前情提要，并在画面右下方浮动提示 **“已自动续播至第 X 集”**；
- 若您希望彻底抹除浏览痕迹，可在个人中心“历史记录”页点击右上角“清空”，系统将从云端服务器彻底粉碎该账户名下的所有播放时间戳。

## 05. 终端实操：通过控制台审查播放器底层核心属性

网页端与 PWA 端的技术爱好者，可以直接在浏览器控制台（按 F12）通过标准 HTML5 媒体 API 实时查看短剧播放器的底层运行状态：

```javascript
// 获取当前页面正在渲染的短剧视频实例
const video = document.querySelector('video');

// 审查核心播放参数
console.table({
  '当前播放时间点 (s)': video.currentTime.toFixed(2),
  '单集总时长 (s)': video.duration.toFixed(2),
  '当前实际播放倍速': video.playbackRate,
  '视频源物理宽度 (px)': video.videoWidth,
  '视频源物理高度 (px)': video.videoHeight,
  '网络是否卡顿暂停': video.paused,
  '解码是否掉帧': video.getVideoPlaybackQuality ? video.getVideoPlaybackQuality().droppedVideoFrames : '不支持'
});

// 计算当前视频已缓冲的前瞻时间长度 (Buffer Ahead)
if (video.buffered.length > 0) {
  const bufferedAhead = video.buffered.end(video.buffered.length - 1) - video.currentTime;
  console.log(`当前网络前瞻缓冲安全区: ${bufferedAhead.toFixed(2)} 秒`);
  // 若缓冲安全区持续低于 1.5 秒，代表本地网络下行带宽告急，随时会发生转圈卡顿！
}
```
