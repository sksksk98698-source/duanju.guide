## 02. 公网中继 (Transit / BGP Tunnel) 底层架构与晚高峰丢包机理解密

目前市面上绝大多数低成本代理工具或廉价小机场，采用的是所谓的 **公网 BGP 中继（BGP Transit / Relay）** 架构。

### 1. 公网中继的数据包传输全路径：
用户在手机上点击播放短剧 -> 数据发送至国内中继机房（如广州某云服务器） -> **国内机房发起公网请求，穿越国内骨干网（163/169） -> 到达上海/广州公网国际关口局 -> 跨越公网跨洋海底光缆 -> 到达海外落地机房**。

```
[公网中继致命拥堵瓶颈点示意图]
[用户] ──> [国内普通机房] ──> [国家公网国际关口局 (AS4134)] ──> [公网民用海缆] ──> [海外VPS]
                                       │
                                       ▼ (致命拥堵瓶颈!)
                             [晚高峰 128% 硬件队列满溢]
                             [Tail Drop 尾丢弃机制触发]
                             [无差别丢包率飙升至 35%]
```

### 2. 为什么公网中继在晚高峰必然崩溃？
- **民用出海总带宽的结构性过载**：每天晚上 20:00 至 23:30，全国数以亿计的网民同时使用国际公网，公网国际关口局的交换机硬件队列瞬间被海量流量淹没；
- **尾丢弃机制（Tail Drop）无情丢包**：当骨干路由器内存队列达到 100% 极限时，硬件直接抛弃后续到达的一切 IP 数据报，公网链路丢包率暴增至 **25% - 40%**；
- **TCP 拥塞算法惩罚性雪崩**：流媒体所依赖的 TCP 协议在检测到丢包后，拥塞窗口（CWND）瞬间砍半并触发 RTO 超时死锁；
- **这正是为什么很多廉价小机场白天测速跑分能达到 500Mbps，但一到晚上 8 点点开一部短剧，视频却永远卡在 00:00 秒疯狂转圈的物理底层原因！**

## 03. 物理专线硬核解密：IPLC 与 IEPL 的技术演进与架构差异

与公网中继截然相反，**物理内网专线** 是由电信运营商（如中国电信、中国联通、PCCW、Singtel）在陆地或海底铺设的、面向跨国大型金融机构与跨国企业通信的**封闭式专用物理光纤网络**。

### 1. IPLC（International Private Leased Circuit - 国际私有租用线路）
- **技术底层**：基于物理层（Layer-1）与时分复用（TDM / SDH）传输网的点对点点物理光缆租用通道；
- **核心特质**：
  - 真正的点对点纯物理光纤直连，中间没有任何公网路由器参与路由寻址；
  - **全程 100% 不经过国家公网国际关口局**，根本不存在公网关口局拥堵与尾丢弃的概念；
  - 物理级 SLA 专线保障，丢包率持续稳定在 **0.0% - 0.1%** 的极限水准；
- **局限性**：物理层租用成本极度高昂，带宽调整极度僵硬，属于第一代传统跨国物理专线。

### 2. IEPL（International Ethernet Private Line - 国际以太网专线）
- **技术底层**：基于现代 OTN（光传送网）与以太网二层透明传输（Layer-2 Tunneling）的新一代企业级专属内网；
- **核心优势**：
  1. **继承物理专线的零公网拥堵基因**：数据全程在专用物理光纤内网二层封装传输，完全绕开公网国际出口，绝对免疫运营商的晚高峰 QoS 限制与 DPI 流量审计；
  2. **端到端极致超低延迟与零抖动**：广深至香港物理传输时延恒定仅 **3.2ms**，沪杭至香港仅 **18.5ms**，端到端往返抖动（Jitter）小于 0.5ms；
  3. **超强突发吞吐弹性**：原生支持万兆接口与单节点 2.5Gbps 超大管道并发，完美适应超高清短剧在滑屏瞬间对数十兆带宽的极端吞吐渴求。
